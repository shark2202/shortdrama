## 0. 产线组成（一句话）

```
题材 → [pi-agent 写剧本] → story.json → [Z-Image 出定妆图] → cast/*.png
     → [H3 ref2va 逐镜出镜] → clips/*.mp4 → [ffmpeg 拼接/放大/烧字幕/限幅] → episode.mp4
     → [ffmpeg 质检] → report.json
```

- **谁干什么**：pi-agent 当编剧 + 调度 + 挑图 + 质检；ComfyUI 当画 + 拍；ffmpeg 当剪。
- **不重造轮子**：ComfyUI 客户端用 `h3turing` 包，工作流用 `minimax-h3-turing/workflows/api/` 里的现成 JSON，
  放大用 `minimax-h3-turing/scripts/upscale_video.py`。
- **不引入数据库**：一集 = 一个目录，目录即状态，任何阶段可单独重跑。

> 成本换算表（用于决策"在哪一步多花 1 分钟"）：

| 想知道什么 | 用什么看 | 成本 | 晚了才发现的代价 |
|---|---|---|---|
| 剧本/schema/中英/性别对不对 | `lint` | **10 s** | 一整集 |
| 造型够不够具体、会不会出大众脸 | `facecheck` | **秒级** | 一次重出 10 s/张 ×3 张 ×3 角色 |
| 画面内有没有要读的文字 | `textcheck` | **秒级** | 一整集 |
| 构图/人物对不对 | `frames`（每镜 1 张图） | **10 s/镜** | 一镜 210 s |
| 成片对不对 | `review`（抽帧拼图） | **30 s** | 一镜 210 s + 后期 2.5 min |
| 技术规格过不过 | `qc` | **60 s** | 交付被退 |

## 2.5 优化后的工作流：关键帧先行 + 审片前置

> 原则：**把便宜的判断提前**。出图 10s/张，出镜 210s/镜。
> 剧本/构图/人脸对不对，应该在 1 分钟内知道，而不是 21 分钟后。

```
lint ──► cast ──► pick ──► shots ──► frames ──► [审片] ──► render ──► review ──► assemble ──► qc
 秒级    70s      秒级     秒级      60s        人看      21min      30s        60s        30s
 └─ 剧本预检：毁集级错误在这里挡下（10 秒成本）
 └─ 关键帧：每镜 1 张图（10s），一屏拼图审片
 └─ review：视频抽帧拼图 + manifest.json，废镜在这里发现
```

| 优化点 | 原来 | 现在 | 省下什么 |
|---|---|---|---|
| 剧本错误 | 出图/出镜之后才发现 | `lint` 10 秒挡住 | 一整集 |
| 构图/人物错 | 21 分钟后看片才发现 | `frames` 60 秒出 6 张图，一屏审 | 每错一镜省 210s |
| 废镜返工 | 等成片才发现第 3 镜废 | `review` 在 assemble 前 | 重拼+重放大+重烧字幕 ≈ 1.5 min |
| 后期中间件 | 每次 assemble 重拼+重放大 | `_fresh()` 判断，新旧复用 | ≈ 40s/次 |
| 质检 | 每镜解码 3 遍 | 一次解码多滤镜 | 快 3 倍 |

**关键帧的两种用法**（`frames` 之后二选一）：

| 出镜阶段 | 构图可控性 | 适用 |
|---|---|---|
| `render`（ref2va / t2v） | 文本驱动，构图自由 | 关键帧只做**审片蓝图**（推荐先用这个） |
| `render-i2v` | 关键帧当首帧，构图 100% 可控 | 构图必须精确、或关键帧已经满意时 |

> 代价：`render-i2v` 的首帧会锁死构图，运镜/动作自由度下降；本次 6 镜用 `render`（ref2va）
> 构图更自由、人脸一致，所以**关键帧先行的第一价值是审片，不是驱动**。

**新增字段**：`story.json` 的每个 scene 加 `prompt_cn`（中文画面描述：景别+构图+光线），
关键帧图直接用它；没有就退回用 `beat` 凑（构图会偏）。
**实测（2026-11-03）**：6 镜关键帧 70 秒（10–20s/张），画面质量与 ref2va 成片相当

### 关键帧的审片边界（实测 E01 35 镜后总结）

| 关键帧**能**审 | 关键帧**不能**审 |
|---|---|
| 景别对不对（wide/特写/越肩） | **人脸一致性**（t2i 无参考图，脸/年龄/性别都会漂） |
| 动作对不对（beat 的动作有没有演出来） | 跨镜表演连贯性 |
| 道具/场景/光线/氛围 | 运动与音画同步 |
| 剧情点是否成立（照片、袋子、字迹） | 运镜（关键帧是静态图） |

→ **关键帧 = 提示词与画面的对齐检查器**（10 倍成本差）；人脸一致性必须看
`qc/frames_sheet.png`（ref2va 成片抽帧）。两边合起来才是完整审片。

**实测 E01（35 镜，关键帧口径）**：合格 20 · 重出 10 · 修词 4 · 保留 1。三类硬伤：
① **景别错配（结尾三镜）** —— beat 写"字迹特写"，模型给远景。
   修法：景别词写进 `prompt_cn` 并**显式否定全景**（"特写，画面里只有照片背面"）。
② **人物漂移** —— 关键帧里陈渡出成 40-50 岁灰白发、s26 把林晚画成男人（t2i 固有限制）。
③ **动作/场景错** —— s02 撩头发≠盯照片、s15 人在街上≠店内走三步。

> ⚠️ **这组数字后来被推翻了**（见 §5.21）：上面 29 镜"重出"是**关键帧口径**的误判，
> 复核成片后真缺陷只有 7 镜。根因就是 **`prompt_cn` 缺失时关键帧拿 `beat` 兜底**。
> 补齐 `prompt_cn`（105 镜）后重出关键帧，与成片的吻合度显著提升（E02 实测：划痕/照片入画/
> 箭头/撕口半张脸/唇语镜全部对上）→ **关键帧可以从"误判源"变成"预审工具"**，
> 但验收仍然只认成片。

### 2.6 字幕两条纪律（字幕是观众唯一能读到的信息）

| 纪律 | 规则 | 依据 |
|---|---|---|
| **相邻重复 = 噪音，去掉** | 同一句在 ≤2 镜内重复 → 成片只烧第一次 | 观众 5–10 秒内看两遍同一句＝出戏 |
| **隔得远的重复 = 回环，留住** | 同一句隔 ≥3 镜再出现 → 必须保留 | E01 把"你该回来了。"放在 s11/s23，是同一场戏演两遍（钩子预演 + 正片），第二次才有分量 |

**别用全局去重**：会抹掉叙事回环（踩过：E01 的设计被去重吃掉）。
实现见 `episode.py build_srt`（去重窗口 2 镜）与 `qc`（相邻重复告警 / 回环记入 report.json）。

**覆盖率口径**：`subtitle_cn` = 上屏信息（时间戳、信息卡、对白字幕）；`dialogue_cn` = 口播台词。
质检分开算：有效字幕（去重后）/ 台词；**两者都 <15% 才告警**（悬疑氛围片天然台词少，
原 40% 阈值把 E02 这种"8 条全是有效对白"的集也误判了）。

## 2.8 交付门禁（客观可验收，全部由 `qc` 自动判定）

> 原则：**品味里能被量化的那部分，交给机器判；不能量化的，交给人/外部判**（见 §8）。
> 下面每条都有实测数字，不是拍脑袋的目标值。

| 维度 | 交付标准 | 判据 | 级别 |
|---|---|---|---|
| 分辨率 | 1920×1056（源 640×352 的 3×） | `probe` | 阻断 |
| 帧率 | 24 fps | `probe` | 阻断 |
| 成片时长 | 与剧本各镜合计 ±0.5 s | `probe` vs `story.json` | 提示 |
| **整体响度 I** | **-16 LUFS ±1**（手机外放可到 -14） | `ebur128` | 提示 |
| **真峰值 / 样本峰值** | **≤ -1.0 dBFS**（含 AAC 编码过冲） | `volumedetect` | **阻断** |
| **响度动态 LRA** | **≤ 12 LU**（集与集一致；电影感 20+ 在手机外放忽大忽小） | `ebur128` | 提示 |
| 字幕覆盖率 | ≥ 40% 的镜头有字幕 | `shots.json` | 提示 |
| 黑帧 | 无 | `blackdetect` | 阻断 |
| 缺镜 | 无 | 文件存在性 | 阻断 |
| 单镜静音段 | 尽量无（>1s） | `silencedetect` | 提示 |
| 单镜音轨 | 每镜都有 | `probe` | 提示 |

**响度链（唯一正确的写法，实测）**：

```bash
# 两遍 loudnorm：先测后用，才能命中目标（单遍实测要 -16 得到 -18.1）
LIMITER="alimiter=limit=0.891:attack=1:release=50:level=disabled"
# 第一遍：-af loudnorm=I=-16:TP=-1.5:LRA=12:print_format=json → 拿 measured_*
# 第二遍：loudnorm=...:measured_I=..:measured_TP=..:measured_LRA=..:measured_thresh=..:offset=..:linear=true
# 完整链：$LIMITER,$SECOND,$LIMITER
```

三个必须记住的点（每一条都是踩出来的）：
1. **`alimiter` 的 `level` 默认 true（自动电平）会把限掉的电平推回去** —— 这是成片削波的直接成因（链末端 -0.5 dB → AAC 编码后 0.0 dBFS，数字削波）。必须写 `level=disabled`。
2. **AAC 重编码有 +0.5 dB 过冲** → 滤镜端要压到 -1.5 dBTP，成片才 ≤ -1.0 dBFS。
3. **单遍 loudnorm 不命中目标**，LRA 目标也不生效（实测 LRA 21 压不到 12）。必须两遍。

代码：`shortdrama/loudness.py`（`measure()` / `audio_chain_for()` / `check()`），已接进 `assemble` 与 `qc`。
## 2.9 在 TUI 里怎么审核（图/视频/文档都看不见的时候）

herdr TUI 没有图片与视频预览，**审核不能建立在"人肉眼看图"上**。三条路，按成本从低到高：

| 路径 | 命令 | 适合 |
|---|---|---|
| **只看文字**（首选） | `cat <job>/qc/review.md` | 审核单：每镜一行（角色/字幕/关键帧/视频/时长/seed/结论/备注）。`review` 阶段自动生成 |
| **终端看图** | `/home/a/ai-work/.venv/bin/python shortdrama/tview.py <job>/qc/keyframes_sheet.png` | Pillow → ANSI 真彩色半块，直接打在终端里（本机没装 chafa/viu/img2txt） |
| **浏览器看大图/视频** | `./sd assets serve <job-dir> --port 8092` | 给人看：图直接渲染、视频内嵌播放；递归扫子目录（cast/ frames/ clips/ qc/） |

**视频没有 ANSI 化的办法** → 统一走"抽帧成图"：`review` 已经把每镜第 2.5 秒抽成 `qc/vNN.png`
并拼成 `qc/frames_sheet.png`，用上面的终端/浏览器路径看即可。

**文档**：`.md`/`.txt` 在 TUI 里直接读；PDF 用 `pdftotext x.pdf -`；其他格式用
`libreoffice --headless --convert-to txt x.docx`（本机有 pdftotext / libreoffice）。

**分工原则**：agent 看图（模型侧能拿到图像）→ 把结论写进 `review.md` 的「结论」列；
人只做**拍板**（合格/重出 + 原因），不必自己开图。这是 TUI 环境里唯一成立的审核闭环。

| T6 整集 / T7 质检 | `episode.mp4` / `report.json` 且阻断 0 | `episode.py <job> assemble` / `qc` |

- **运行中** = `logs/stage-<key>.pid` 里的 pid 还活着；输出落在 `logs/stage-<key>.log`，
  网页读这个尾巴当心跳（没有心跳 = 页面上看着像卡死）。
- **两种执行者**：看板的「执行者」下拉框切 `cli`（本地命令跑确定性阶段）或 `agent`
  （起 `pi --print --mode json` 无头 session，把这张任务卡当提示词交给 agent 内核）。
- 写操作要令牌（局域网开放时自动生成）；**看板不存状态**，一切回读 job 目录（D11/R19）。

## 3. 每阶段的"人/agent 该做什么"

### P1 剧本
- schema 见 `prompts/story.md`。中英双轨：`prompt_en`/`sfx_en` 英文喂 H3，其余中文给人看。
- **每镜一个 `primary` 角色**——它决定这一镜用谁的定妆图当参考。

### P2 台词 / 字幕（信息通道，不是装饰）
- 实测初版 105 镜只有 17 条对白 → 观众三分钟读不到信息。**补台词是单独的一个阶段**。
- **选镜权在代码，LLM 只写字**：`tools/add_dialogue.py` 里 `pick_targets()` 决定哪些镜要台词，
  LLM 只负责写内容（≤16 字、不解释、不剧透、不许留空）。第一版把选镜也交给 LLM → 它全留空
  还覆盖掉已有字幕。
- **合并而不是覆盖**：已有字幕的镜不动（`merge()`）。
- 只改文本 → **不用重渲**：改完跑 `shots`（秒级）→ `assemble`（1.5 min）→ `qc`。
- 质检口径：有效字幕（去重后）与台词数**分开算**，两者都 <15% 才告警。
### P3 定妆图（这一步最值钱）
- 出 3 张候选 → **必须真的看图挑**（agent 用 read 工具直接看 PNG），别省这一步。
- 挑法：主图 = 脸最正、最清楚、五官无遮挡；备图 = 同一张脸但角度略不同（给 ref2va 一点变化余地）。
- 选择写进 `cast/selection.json`：`{"c1": {"main": "cand1", "alt": "cand2"}}`，再跑 `pick`。
- ⚠️ **描述里不能有遮脸的元素**（见 §5）。

### P4 分镜 + 关键帧
- 句式固定，代码拼好，别手改：
  `<Picture 1> and <Picture 2> show the same character. <动作/镜头/光线>, <风格>, natural ambient audio: <环境音>`
- `<Picture 1>` / `<Picture 2>` = 同一角色的主图 + 备图（ref2va 的一致性来源）。

### P5 出镜
- 后台跑（21 分钟），`clips/NN.mp4` 已存在就跳过 → **单镜粒度续跑**。
- 失败自动换 seed 重试 ≤3 次（`SEED + idx + attempt`）。
- **成片只用可复现档**（ref2va bypass，无缓存加速）。缓存档（FirstBlockCache/TeaCache/T8）会 fork 采样轨迹，同 seed 出不同画面。

### P6 整集（顺序有讲究）
1. **逐镜响度归一**（`loudnorm=I=-20:TP=-3:LRA=11` → `clips/norm/`）再 concat demuxer 逐样本 copy
   （整片归一会把动态压扁；逐镜对齐后整片 LRA 从 20.8 降到 7.4 LU）
2. 3x 放大（`upscale_video.py --scale 3`，lanczos）→ 1920×1056；竖屏直接 scale 到 1080×1920
3. **烧字幕**（libass + Noto Sans CJK SC，白字黑边；横屏 `FontSize=42, MarginV=56`，竖屏 `FontSize=54, MarginV=360` 避开平台 UI）
   —— **只去相邻重复**，隔得远的重复是叙事回环保留
4. **BGM 情绪床**（`assets/bgm.oga`，CC BY 4.0 署名随片）：`amix normalize=0`，
   **必须走 `-filter_complex`**（`-af` 是单输入链，装不下第二路）
5. **整片两遍 loudnorm + 限幅**（`shortdrama/loudness.py` 的 `audio_chain_for()`）——
   单遍不命中目标；`alimiter` 必须 `level=disabled`（默认会把限掉的电平推回去）、
   上限 **-2.0 dBFS**（`limit=0.794`）、**`attack=0.1ms`**（H3 音轨有 ~4ms 瞬态突发，
   attack=1ms 时突发头部样本会越过 0 dBFS 被 AAC 削平）。详见 §2.8。
6. **系列级亮度统一**（`grade.measure_brightness()` → eq 校正到 YAVG 90；三集差 25% 时不统一会跳）
7. H.264 + AAC 48kHz / CRF 18 / faststart
> **与建设方案 §9.5 的唯一差异**：先放大再烧字幕（方案是先烧后放大）。
> 640×352 上烧字再放大 = 糊；1920×1056 上烧清楚得多。字幕时间轴按**实际**每镜时长排。

### P7 质检
`episode.py qc` 自动查：黑帧（blackdetect）/ 静音（silencedetect）/ 削波（volumedetect）/
时长偏差 / 分辨率 / 帧率 / 缺镜 → `report.json`；有阻断项时退出码非 0。

**自动质检不代替人眼**：出片后一定要抽帧看（`qc/contact_sheet.png` 那招）：
```bash
for i in 01 02 03 04 05 06; do $FF -y -ss 2.5 -i clips/$i.mp4 -frames:v 1 qc/f$i.png; done
$FF -y -framerate 1 -pattern_type glob -i 'qc/f*.png' -vf tile=3x2 -frames:v 1 qc/contact_sheet.png
```
看三件事：**人脸是不是同一个人**、**有没有穿帮/畸变**、**镜头类型对不对**。

## 4. 质检分级（阻断 vs 提示）

| 级别 | 项目 | 处置 |
| 级别 | 项目 | 处置 |
|---|---|---|
| 阻断 | 交付分辨率≠1920×1056、帧率≠24、缺镜、黑帧、**成片样本峰值 > -1.0 dBFS** | 必须重出/重压 |
| 提示 | 整体响度偏离 -16 LUFS 超过 1 LU、LRA > 12 LU、字幕覆盖率 < 40%、单镜时长偏差 >0.5s、无音轨、静音段、**源镜头**削波 | 后期兜底或可接受 |

源镜头的削波（如 02/05 镜 max 0.0 dBFS）由后期 limiter 压住，成片级才阻断——判据是**成片**峰值。
阻断阈值从 -0.3 改成 **-1.0 dBFS**：AAC 重编码有 +0.5 dB 过冲，按 -0.3 判会误报。
完整门禁清单见 §2.8。
## 5. 本次实践踩到的坑

1. **定妆描述遮脸 → 黑眼罩**。
   写"帽檐压低**遮住眼睛**"→ Z-Image 照着画出黑色眼罩，脸全废（c2 前三张全废，重出才修好）。
   规则：`desc_cn` 不写任何遮挡五官的词；需要"神秘"就靠**打光**（半边脸在阴影里）而不是物理遮挡。
2. **H3 源音轨会削波**：本次 02/05 镜 max_volume 到 0 dBFS。→ 后期必须挂 `alimiter`。
3. **扩散模型写不好招牌文字**：便利店霓虹牌上的汉字是乱码（本次可见）。
   规避：镜头构图避开大面积可读文字，或后期贴真实字。
4. **H3 只吃英文**：中文进 `prompt_en` 效果差（不是慢一点，是明显更差）。
5. **同一 prompt 会被静默去重**：ComfyUI 的 prompt_id 由输入决定 → seed 必须每镜递增。
6. **本机没有 ffprobe**：`ffmpeg -i` 解析 stderr 拿时长/分辨率/帧率。
7. **显存是唯一硬瓶颈**：本地 LLM（13–17GB）与 H3（≈20GB）不能同驻，流水线阶段必须串行；渲染期间别开别的 GPU 任务。
8. **不给性别/年龄/人种 → Z-Image 默认出男性**。实测：三角色（两女一男）全部出成男的——造型描述里只有骨相/发型/衣着，模型拿不到性别就自己填。→ 身份锚点（`identity_cn` = "亚洲女性，24岁"）**独立成字段**，出图提示词 = 身份 + 造型 + 中性光后缀。`facecheck.py` 出图前硬性校验，不合格直接拒绝渲染。
9. **风格词不能进定妆提示词**：`style_cn`（霓虹洋红/低照度/胶片颗粒）会覆盖"中性柔光、纯灰背景"，模型顺势出美颜网红脸，而且带色光污染 ref2va 的参考图。定妆图要的是干净中性光。
10. **备图必须是主图的 i2i 派生**：直接复制另一张 t2i 候选 = 那是**另一个人**，而 ref2va 的 `<Picture 2>` 要求"同一个角色的另一张"。用错人脸 = 跨镜崩脸。→ `pick` 阶段改成从主图 i2i(denoise 0.65) 派生。
11. **画面里不能有需要观众读懂的文字**：H3/Z-Image 画出的字必是乱码。照片上的日期、监控时间戳、照片背面的手写尾钩全部废掉。→ 可读信息一律进 `subtitle_cn`（后期 ffmpeg 烧，一定正确）；画面内可保留"这里有行字"的质感但必须标明 illegible / too small to read。`textcheck.py` 出图前拦截，`tools/fix_text_shots.py` 定点改写。
12. **物镜必须走纯 t2v**：ref2va 会把提示词强制改成 `"<Picture 1> and <Picture 2> show the same character."`，于是照片背面特写/监控回放/鞋尖滴水也被塞两张脸 → H3 去画人而不是画那个东西。→ 每镜显式声明 `ref`（角色 id 或 `null`），`null` 走 `h3_w4a8_t2v_bypass_api.json` 且不带参考图。`tools/set_refs.py` 逐镜标注（105 镜里 18 镜判为无角色在场）。
13. **跨集必须共用定妆图**：`cast/` 放剧集根，每集目录里软链过去，否则 3 集各出各的脸。
14. **成片削波的真凶是 `alimiter` 的 `level`**（默认 true = 自动电平），它把限掉的电平又推回去；
    再叠加 AAC 编码 +0.5 dB 过冲 → 成片 0.0 dBFS 数字削波。必须 `level=disabled` + 两遍 loudnorm。详见 §2.8。
15. **本地 LLM 开 reasoning 会吃掉 `max_tokens`**：要 35 镜的 JSON 时，reasoning 吃掉一半预算、
    content 直接返回空字符串。→ 脚本必须把"只有 reasoning、content 为空"明确报出来（别让人对空串猜），
    并且**分块生成**（12 镜/块），长 JSON 一次写完必被截断。
16. **35 镜 × 5.17 s 是"电视剧节奏"**：平均镜长 5.17 s，3 分钟只有 35 个切点；
    快节奏竖屏短剧约 1.6–3.1 s（70–110 个切点）。H3 的 124 帧是硬约束，**不能靠缩短镜头提速**——
    只能靠剪辑层造节奏：镜内运动 + 前景遮挡做隐形剪辑、J-cut/L-cut、字幕条跳动当节拍器、
    用环境音的瞬态（雨停/门铃/心跳）制造断点。
17. **画面内文字必乱码 / 物镜会被画成人物 / 不给性别就出男性** —— 这三条不是模型"不稳定"，
    是**输入约束没写**：写进提示词 + 加检查器就稳定了。见上面 8 / 11 / 12 条。
18. **105 镜里有 18 镜是"物镜"**（照片背面、监控回放、鞋、剪影、环境）。这类镜走纯 t2v（无参考图），
    渲染还更快（180 s vs 210 s）。
19. **成片没有 BGM**：现在音轨只有各镜 H3 原生环境音。短剧是听觉媒介，BGM + 混音 ducking
    是最低成本的品味提升（比 TTS 便宜得多）。⚠️ 目前**未做**。
20. **画幅是横屏**：交付 1920×1056，但抖音/红果要 1080×1920（9:16）。方案里"竖屏"出现 0 次。
    换算：中心裁 9:16 只剩 31% 宽度（11 个全景镜会废）；全宽塞竖屏则 69% 屏幕是空的（正好放字幕条/角色条）。
20. **画幅是横屏**：交付 1920×1056，但抖音/红果要 1080×1920（9:16）。方案里"竖屏"出现 0 次。
    ⚠️ **已于本版解决**：实测 H3 工作流支持 `width/height`，**原生出竖屏**（352×640，构图与人物一致性都正常）。
    `story.json` 加 `"aspect": "portrait"` → render 出 352×640、assemble 缩到 **1080×1920 满屏**。
    后期裁切/留黑只作为兜底（`shortdrama/vertical.py`）。重渲 105 镜竖屏 ≈ 6.2 h。

### 21. ⚠️ **审片依据必须是成片，不是关键帧**（今晚最贵的教训）

我先用**关键帧**（t2i 生成）审了 105 镜，判出"29 镜重出 + 17 镜修词"；
改词准备烧 3 小时 GPU 时，回头看**成片抽帧**，发现：
**成片几乎全对**（s3 真是全景、s7 陈渡不显老、s26 雨里跑的确实是女性、
E02 五镜唇语全部正确），**真缺陷只有 6–7 镜**。
根因：`prompt_cn` 缺失时关键帧是拿 `beat` 兜底生成的，而 H3 实际吃的是写得很细的 `prompt_en` ——
**两条提示词路径不同，关键帧根本不能代表成片**。

→ **纪律：审片只认成片抽帧（`qc/frames_sheet.png`）。**
关键帧只能当"提示词→画面"的粗检查（而且必须补齐 `prompt_cn`），**不能用来判定成片缺陷**。
→ 这次若没复核，省下的是 3 小时 GPU，浪费的也是 3 小时 GPU。

### 22. ⚠️ **占位字幕（"……"）比没有字幕更糟**

并行会话用 LLM 补台词，留了 21 条纯省略号/占位（烧出来观众只看到三个点）。
→ 质检加一条：**`subtitle_cn` 只含省略号/标点 = 占位，必须替换**（`tools/apply_patches.py` 会只覆盖占位）。

### 23. ⚠️ **画面里的模型中文会被观众读出来**

扩散模型会在照片/招牌上写"像中文的乱码"，观众会真的读。
E01 s1 的旧照片上写着与剧情无关的字（"我记得这味道…"）→ 观众会以为是线索 → **发布级事故**。
→ 关键道具上的字要么让模型**模糊不可辨认**（提示词要显式写"no readable writing"），
要么**后期贴真字**（像字幕一样烧）。剧本里"照片背面写着某句话"这种设计，
**必须确认模型是否真的写对了字**，否则就是穿帮。
→ 反过来，E01 s12/s32/s34/s35 的手写字恰好与剧情一致（"如果你看到这张照片…"）→ 白捡，
因为**物件驱动的镜头，模型连字都能对上**。

## 7. 规模化怎么排（实测数据）

**本机实测（3 集 × 35 镜 / 3 分钟 / 105 镜）**：

| 项 | 实测 |
|---|---|
| 单镜出镜 | 210 s（ref2va）/ 180 s（t2v 物镜） |
| 一集 35 镜 | **2.1 h GPU** |
| 三集 105 镜 | **6.2 h GPU**（串行）+ ~1 h agent 交互 |
| 成片体积 | 137 MB / 180.9 s ≈ **6.1 Mbps**（上传偏重，可压到 3–4 Mbps） |
| 磁盘 | 每集 ≤300 MB，成片 + 中间产物 |

排产规则：
- **渲染是瓶颈**，单卡串行，加机器没用（只有 1 张卡）。阶段之间必须串行（显存不够，见 §5-7）。
- **一集一集排**，不要并行开两集。
- 提速选项：草稿档（i2v-draft，约 103 s/镜）看构图，锁定后再用 bypass 档出片——**草稿不能直接进成片**。
- 下一步（未做）：本地 TTS 配音 + 对轨（方案 P2）；H3 音轨与 latent 帧数绑定，插帧不会延长声音。

## 8. 品味层：自动化查不了的部分（**必读**）

> 前面所有门禁都是**客观**的：响度、峰值、黑帧、缺镜、字幕覆盖率。
> 它们能保证"不难看、不断片、规格对"，**保证不了"好看"**。

### 8.1 AI 不是评审者

本项目的 agent（包括我在内）说"这段有电影感/氛围感拉满"——这是**训练数据里的套话，不可证伪**。
模型没有观众、没有偏好、没有后果，它的"品味"就是分布平均，而分布平均的定义就是"没有品味"。
所以：

- agent 的判断在证据等级里排 **L0（零证据）**，只在"结构是否可数/可对照"时才有价值（镜数、钩子位置、反转密度、镜长分布）。
- **品味这一层必须交给外部。**

### 8.2 证据分级

| 级别 | 证据 | 能证明 | 不能证明 |
|---|---|---|---|
| L0 | agent 说"好看" | 零 | 不可证伪 |
| L1 | 客观门禁全过（§2.8） | "不难看、不断片、规格对" | "好看" |
| L2 | 结构合规（钩子/反转/尾钩位置、信息密度） | "不落后于行业范式" | "好看" |
| L3 | 与真实爆款样本逐项对照 | "不偏离爆款范式" | 爆款是结果不是标准 |
| **L4** | **真人盲测**（5–10 个目标受众，不告知版本，问"哪集让你想看下一集"） | **"好看"** | 样本小、只对特定人群成立 |
| L5 | 平台真实数据（3 秒完播 / 完播率 / 复看） | 唯一终极判据 | 只在发布后，不可控 |

**当前状态：只有 L1。** L2 的"结构模板"还是 agent 自己写的 → 闭环未打破 → 做多少集都是在放大同一个未验证的假设。

### 8.3 验证协议（按成本从低到高）

1. **今天能做（0 成本）**：拉 10 部同题材真爆款做**分镜拆解表**——钩子在第几秒、反转在第几秒、
   尾钩留多少、平均镜长多少。我们的数字 vs 它们的数字，**逐行比**。这一步会直接暴露 §5-16 的节奏问题。
2. **一小时（0 成本）**：抽 20 个关键镜做**接触印片表**（`review` 阶段已产出），人眼扫一遍，
   找"说不出哪里怪但就是不对"的镜——那是审片人最先抓的地方。
3. **一天内（几百元）**：找一个真人剪辑/导演看**成片**，只问三个问题：哪镜你出戏、哪句台词假、结尾你想点下一集吗。
4. **一周内（0 成本）**：5–10 个目标受众盲测，两条片子随机分组，问"想看下一集吗"。
   ⚠️ **让真人盲选（二选一），不要让人打分**——人对打分客气，对二选一不会。

### 8.4 三个已知的"品味缺口"（本版未解决，按影响排序）

| 缺口 | 事实 | 影响 | 最便宜的补法 |
|---|---|---|---|
| **画幅横屏** | 交付 1920×1056，平台要 1080×1920 | 竖屏上"中间一条缝"，或 31% 宽度被裁 | 全宽横幅 + 上下信息条（字幕/角色条/花字），不动镜头 |
| **没有 BGM** | 音轨只有 H3 原生环境音 | 短剧是听觉媒介，情绪大半靠音乐 | 一条 BGM 床 + 混音 ducking（比 TTS 便宜得多） |
| **节奏偏慢** | 平均镜长 5.17 s | 感知"慢一倍"，完播率吃亏 | 剪辑层造隐形剪辑 + 用环境音瞬态当断点 |

（另有"没有台词配音"——这是 D7 的**刻意取舍**不是缺陷，但做外部对照时要记住：纯字幕短剧在专业评审里会被判低分。）

### 8.5 领域专家怎么想，以及**没有画面**时怎么复刻

> 前提：现在只能 SSH 进服务器、只有 TUI，看不到图和视频。
> 那问题就不是"怎么用眼睛看"，而是"专家的判断里，哪些部分本来就不需要眼睛"。

**专家的循环 = 假设 → 取证 → 归因 → 取舍**（不是逐帧匀速看）：

1. **先有假设**：这一镜要干什么？我担心什么？（"第 21 镜是尾钩，观众会不会划走"）
   不带假设看片的人只会说"感觉不对"。
2. **分层下钻**：先扫全片找异常 → 只看可疑镜 → 才逐帧。专家的时间是**花在异常上**的。
3. **归因到模式，不归因到单点**：一个镜的问题往往是作者的系统性选择
   （所有物镜都被画成人、角色年龄逐镜漂移、台词全是省略号）→ 改一处不够，要改规则。
4. **取舍带成本**：重渲一镜 210s。专家会问"这镜承担什么功能，删掉会怎样"——
   值不值 210s，是评审的一部分。
5. **结论可证伪**："她的脸比上镜年轻十岁" ✅ / "人设有点崩" ❌。
6. **对已知缺陷分布有经验**：H3 口型必错、招牌字必乱码 → 看到直接归类为已知缺陷，
   不浪费讨论时间，改剧本绕开（这本身就是专家级效率）。

**专家的参照系**（判断的锚点）：① 剧本意图（这镜要推进什么）② 上下文连续性（前后镜）
③ 平台惯例（3 秒留存 / 尾钩）④ 同类爆款 ⑤ 已知渲染缺陷分布。

**在 SSH/TUI 里复刻这张循环**（本工程已实现的"取证自动化"）：

| 专家的动作 | 无图环境里的替代 | 落点 |
|---|---|---|
| 扫全片找异常 | 每镜客观事实：亮度 / 饱和 / 静止秒数 / 与上镜相似度 / 关键帧vs成片 PSNR | `qc/evidence.md`（`shortdrama/evidence.py`，35 镜 ≈ 4 秒） |
| 只看可疑镜 | 证据表自动给"**先看这 N 镜**"优先级排序（跳变/过暗过曝 > 重复/静止） | 同上 |
| 比对上下文 | 与上镜的签名距离、亮度跳变——自动算好的数 | 同上 |
| 判断该信哪条证据 | 证据表直接量化"关键帧 vs 成片 PSNR 中位 **12 dB**" → 关键帧整体不能代表成片（§21） | 同上 |
| 拍板 | **最小动作集**：通过 / 重出 / 改词（引用原文+改成什么）/ 降级（可接受，记备注）→ 写回 `review.json` | `sd studio` 写，SSH 侧只读 |

**每轮评审只做三件事**（这是把专家的"注意力预算"抄下来）：
① 阻断项（qc 报出来的）② 证据表排前 N 镜 ③ 随机抽 3 镜（防"只挑有问题的看"）。
不要追求"全片看一遍"——专家也不看。

**诚实的边界**：节奏感、情绪、演员感、镜头调度——这些"品味"在纯文本里**做不了**。
所以分工只能是：
- **取证**（找异常）→ 自动化（证据表）；
- **归因与取舍**（为什么错、值不值得修）→ 人，或能看图的 agent 代看并把结论写成文字；
- **真正需要眼睛的结论**（节奏、情绪）→ 必须在有屏幕的设备上看（手机/平板打开审片台，
  只回写结论），SSH 侧只读决定文件。

> 一条不能破的纪律：**别用不可信的证据下结论**。我们用关键帧审 105 镜，误判了 29 镜，
> 而真正该修的只有 6–7 镜（§21）。证据表的作用之一，就是让"哪条证据可信"变成可核对的事实。


## 9. 审片台（TUI 与 Web 协作）

pi-agent 的 TUI **不能显示图片和视频**，而方案 §11.2 说真正的瓶颈是人工审片。
所以短剧工程自带一个本地审片界面：

```bash
cd workspace/shortdrama
./sd studio                      # 本机 → http://127.0.0.1:8095/
./sd studio --host 0.0.0.0       # 局域网审片（手机上看）→ 打印带令牌的 URL
./sd studio --status             # agent 在 TUI 里问"人审完了吗"
```

局域网审片的三条纪律：
1. **写操作必须带令牌**（URL 的 `?k=…` 或 `X-Studio-Token` 头），否则 403 ——
   因为「重出」会**删 clip**，不能让同网段任何设备都能删。
   读操作（看片）不设限。
2. **默认仍是 127.0.0.1**；开放局域网要显式 `--host 0.0.0.0` 并自己承担风险（与 R5 同源）。
3. 手机浏览器打开带令牌的 URL 即可；令牌同时存 sessionStorage，之后的 POST 自动带上。

界面四个页签：**分镜审片**（逐镜视频/关键帧 + 通过/重出 + 备注）、**定妆选图**（点选主图/备图）、
**任务看板**（阶段卡片 + 一键触发）、**成片与质检**（播放器 + findings + agent 日志尾巴）。

无图环境下的评审入口是 **`qc/evidence.md`**（证据表，见 §8.5）：
```bash
python3 shortdrama/evidence.py /home/a/ai-work/duanju/D202611_001_E01   # 35 镜 ≈ 4 秒
```
它给出每镜的亮度/静止/关键帧 PSNR/与上镜相似度，并排出"先看这 N 镜"——人在 SSH/TUI 里
先看这 N 镜 + 阻断项 + 随机抽 3 镜，而不是全片扫。

协作闭环（状态全在文件里，无数据库）：

```
agent 写 job 目录 ──▶ 浏览器读 ──▶ 浏览器写决定 ──▶ agent 读决定
cast/selection.json   （挑图：pick 阶段本来就读它）
review.json           （逐镜通过/重出；"重出"= 删 clip，下次 render 只重出这一镜）
```

安全：默认绑 **127.0.0.1**（ComfyUI 无鉴权是已知风险 R5，别再加一个）；要局域网访问用 `--host 0.0.0.0` 并自行承担风险。
